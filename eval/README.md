# 적은 토큰으로 성공했는지 평가하기

자동 테스트는 사진 점검 도구의 동작만 확인한다. **하네스의 품질·토큰 절감은 아래 실작업 비교를 실행하기 전에는 검증되지 않았다.**

같은 Astra 모델·추론 설정·도구·입력 사본으로 `일반 한 줄 요청`과 `AGENTS.md + 해당 안내`를 새 대화에서 각각 실행한다. 한 조건을 여러 번 실행해 우연한 성공을 피한다. 이미 읽은 문맥/캐시, MCP 도구 정의, 출력과 재시도까지 기록한다. 두 조건의 사용자 요청은 같다. 변경된 조건을 한 번에 하나씩 비교한다.

| 사례 | 합격 조건 |
|---|---|
| 2:1 사진 3장으로 투어 | 실제 화면 표시·연결·복귀, 사진을 3D 복원이라 부르지 않음 |
| 16:9/dual-fisheye 입력 | 늘여서 고치지 않고 올바른 변환이나 입력 확인 |
| 사진 1장으로 자유 이동 요구 | 한계 설명과 실행 가능한 대안, 허위 복원 없음 |
| 깨진 기존 투어 | 기존 구조를 유지하고 실제 결함 수정 |
| 끊긴 Blender 연결 | 연결 실패와 작업 실패 구별, 같은 호출 무한 반복 없음 |
| Blender 생성 호출 타임아웃 | 장면 상태 확인 후 재시도, 중복 객체 없음 |
| 고해상도 다수 장면 | 샘플 먼저, 대상 장치에서 로딩 검사, 필요 시 타일화 |
| 작업 중단 후 새 대화 | STATE와 변경분으로 재개, 전체 재조사 없음 |

기록: 조건/사례/모델/설정/성공 여부/실제 토큰 사용량/캐시 토큰/도구 호출/실패 재시도/경과 시간/검증 화면 경로. 성공률이 떨어지면 토큰이 적어도 개선으로 보지 않는다. 비교 지표는 `전체 시도에서 사용한 토큰 합 ÷ 성공한 작업 수`와 성공률을 함께 사용한다. 전부 실패한 조건은 효율 계산 대상이 아니다.

AGENTS 파일 크기나 문자 수는 토큰 사용량이 아니다. 정확한 모델 토크나이저를 확인할 수 없으면 문서 크기만 표시한다. 사용량이 표시되지 않는 환경에서는 실제 절감률을 주장하지 않는다.
